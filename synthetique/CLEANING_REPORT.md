# Cleaning report – Health Retailers data set

Generated by `clean_data.py --synthetique` from the SYNTHETIC data in `externe/donnees_synthetiques/` (01/05/2025 → 29/09/2026), with the real reference files of `fichiers/`. Only the files built from generated data are kept here; the real cleaned files are in `cleaned/`.

## Rules applied to every file

- Read with the right encoding (UTF-8 or Windows-1252) and delimiter (`;` or `,`), written back as **UTF-8, comma-separated**.
- **Original column names are kept unchanged** (only the broken accents of the Produits header were restored: `Libell�` → `Libellé`, and the pipes removed from CompaniesList: `| Name |` → `Name`).
- Columns ADDED by the cleaning are named in the software's style (`Product_Id`, `IsValidated`, `CaisseName`…); values extracted from a JSON column are named `<JsonColumn>_<jsonKey>` (e.g. `Extra_cump`, `Data_qte`).
- Leading / trailing spaces trimmed in every cell.
- **Decimal comma → decimal point** (`42,38` → `42.38`).
- **Dates → ISO 8601** (`9/30/2024 8:28` and `30/09/2024 08:28` both → `2024-09-30 08:28`). The day/month order is detected per column (a value > 12 tells which part is the day).
- **Booleans → true / false** (`VRAI/FAUX`, `TRUE/FALSE`).
- Columns that are 100 % empty or always 0 dropped; exact duplicate rows removed.
- Rows are never silently corrected: doubtful values are **flagged** in an extra column, not changed.
- Personal / secret data removed: password hashes, e-mails and phone numbers.

## What was done to each file

### `product_stocks.csv`  ←  ProductStocks.csv

*Current stock level per product (snapshot at export date).*

1. Read `ProductStocks.csv`: 6,842 rows × 5 columns, encoding UTF-8, delimiter `;`.
2. Decimal comma → decimal point in: Quantity, TotalQuantity.
3. `TotalQuantity` is identical to `Quantity` on every row (single store) → dropped.
4. `Stock_Id` values: {'1': 6842} → only one store/warehouse, column dropped.
5. Added `StockStatus` (IN_STOCK / OUT_OF_STOCK / NEGATIVE). 339 products have a negative stock (sold before the purchase was recorded) – flagged, not changed.
6. Original column names kept unchanged. Columns added by the cleaning: `StockStatus`.
7. Dropped column(s) not useful for analysis: Stock_Id, TotalQuantity.

**Output columns:** `Id`, `Product_Id`, `Quantity`, `StockStatus`

### `documents.csv`  ←  Documents.csv

*Header of every sale / purchase document (fact table header).*

1. Read `Documents.csv`: 33,326 rows × 35 columns, encoding UTF-8, delimiter `,`.
2. Booleans VRAI/FAUX/TRUE/FALSE → true/false in: IsDelivered.
3. Dates converted to ISO format (YYYY-MM-DD[ HH:MM]) from: DocumentDate (MM/DD/YYYY), CreatedDate (MM/DD/YYYY), ModifiedDate (MM/DD/YYYY), ValidatedDate (MM/DD/YYYY).
4. Dropped 4 column(s) that are 100 % empty: Observation, UserComment, Attachments_Id, DiscountAmount.
5. Dropped 4 column(s) that are always 0 (no information): IncludedTaxes, TotalRetenueSurHt, TotalRetenueSurTva, TotalRetenueSurTtc.
6. Parsed the `Extra` JSON: key `cosld` = customer balance before the document → `Extra_cosld` (30,791 rows).
7. Added `DocumentTypeName` (name) and `Flow` (SALE / PURCHASE / …) from document_types.csv.
8. Added `IsValidated` from `State` (1 = validated, 0 = draft). 81 draft documents are kept but should be excluded from revenue.
9. Added `PaymentModeName` name from `PaymentMode_Id` (1 Cheque, 5 Bank card, 7 Credit, 11 Cash, 21 Tokens).
10. `DocumentDate` has no time (always 00:00) – use `CreatedDate` for the hour of the sale.
11. Original column names kept unchanged. Columns added by the cleaning: `DocumentTypeName`, `Flow`, `IsValidated`, `PaymentModeName`, `Extra_cosld`.
12. Dropped column(s) not useful for analysis: DefaultStock_Id, DiscountPercentage, Extra, TotalExtraTaxes, TotalTaxes (raw `Extra` JSON parsed into `Extra_cosld`, `DefaultStock_Id` single store).

**Output columns:** `Id`, `DocumentNumber`, `DocumentDate`, `DocumentType_Id`, `DocumentTypeName`, `Flow`, `State`, `IsValidated`, `Transaction_Id`, `PaymentMode_Id`, `PaymentModeName`, `ProductPriceName_Id`, `TotalHt`, `TotalDiscount`, `TotalNetHt`, `TotalTva`, `TotalTtc`, `Timbre`, `FinalPrice`, `IsDelivered`, `Extra_cosld`, `CreatedDate`, `CreatedBy`, `ModifiedDate`, `ModifiedBy`, `ValidatedDate`, `ValidatedBy`

3. Removed the `Tresorerie.` prefix from aggregate and event names; `Data` JSON re-serialised compactly (valid JSON).
4. Event counts: PaymentAdded 29,572, CaisseTransactionAdded 28,446, CaisseDiscrepancyIdentified 1,670, BankAccountTransactionAdded 1,126, CaisseOpened 988, CaisseClosed 988, PaymentRemoved 311, CaisseTransactionCancelled 303, BankAccountTransactionCancelled 8.

**Output columns:** `Id`, `UtcTimestamp`, `AggregateName`, `AggregateId`, `Version`, `EventName`, `UserId`, `Data`

### `cash_register_events.csv`  ←  DomainEvents.csv

*Derived from treasury events: register openings, closings and cash discrepancies (for cash-control KPIs).*

1. Kept only register events (OPEN, CLOSE, DISCREPANCY, DISCREPANCY_APPROVED) and flattened their JSON into columns named <JsonColumn>_<jsonKey>: Data_balance, Data_expectedBalance, Data_foundBalance, Data_amount; plus `EventType` (short code) and `DetectedAt` (OPENING / CLOSING) → 3,646 rows.
